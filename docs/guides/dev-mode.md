# Dev-режим

Цель: «посмотрел — поправил — увидел» без боли.

## Hot reload

`bun run dev` = `bun --watch src/index.ts`: процесс перезапускается при любом изменении файлов (включая `bot.config.ts`). Поправили модуль — команда уже обновлена.

## Мгновенная регистрация команд

Discord кэширует **глобальные** slash-команды до минуты. Чтобы правки команд были мгновенными, в dev-режиме команды регистрируются **на гильду**:

```bash
DISCORD_DEV_GUILD_ID=123456789012345678 bun run dev
```

или в `bot.config.ts`: `devGuildId: '...'`.

- Есть `devGuildId` → команды на гильде (мгновенно).
- Нет → команды глобально (кэш Discord, до минуты).

Для production — просто не задавайте `devGuildId` / `DISCORD_DEV_GUILD_ID`.

## Регистрация команд без бота

Отдельный REST-скрипт — регистрирует команды, не подключаясь к gateway (полезно в CI или при горячей перезагрузке):

```bash
bun run deploy:commands
```

## Проверка без Discord: юнит-тесты

Логика Handler-а — чистая функция: `run(ctx)` не требует сети. Ядро поставляет хелперы из `'../../core/testing.ts'`:

```ts
import { runHandler } from '../../core/testing.ts';

const result = await runHandler(handler, { args: { n: 2 } });
expect(result).toEqual({ kind: 'message', content: '2' });
```

- `runHandler` идёт через реальный `Pipeline` (дефолты, парсинг).
- Всё in-memory: `MemoryStore` ничего не пишет на диск, логгер заглушен.

## Горячая перезагрузка данных

Store модуля — файл в `.data/<module>.json` (неймспейс по модулю). Перезапуск процесса данные сохраняет. Диалоговая память по каналу — in-memory (сбрасывается при рестарте), она для коротких многошаговых сценариев.
