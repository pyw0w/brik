# Event-driven logging lives in a module, on the onReady(client) escape hatch

Система логов обязана реагировать на gateway-события Discord (входы/выходы, удаления/редакции сообщений, голос, баны), которых нет в чистой модели «Input → Result». Решение — не строить мост событий в ядре, а разместить логи в модуле (`src/modules/logs`) и использовать единственный санкционированный выход из контракта — `onReady(ctx)` с сырым `client`. Граница при этом не нарушается: модуль не импортирует discord.js (эмбеды — plain-объекты, структурно совместимые с `APIEmbed`; типы событий текут через перегрузки `client.on`), а каналы настраиваются на сервере командой `/logs` и хранятся в его же `store`. Для приёма событий gateway расширен интентами (`GuildMembers`, `GuildModeration`, `GuildMessages`, `GuildVoiceStates`, `MessageContent`) и партиалами — это host-решение, не контракт. Плата за простоту: модуль сам отвечает за устойчивость подписок (доставка в канал — fire-and-forget с тихим fallback).
