# Services as lifecycle-managed dependencies

Сервис — именованная глобальная зависимость модулей (API-клиент, соединение и т.п.), живущая в `src/services/<name>/service.ts` и объявленная через `defineService`. Сервисы расширяют интерфейс `ServiceMap` (аугментация типов), поэтому `ctx.services.<name>` типизирован. Модуль декларирует нужные сервисы (`services: ['name']`) — ядро строит только их (init до setup модулей, опции из `bot.config.ts` секции `services` с zod-валидацией) и закрывает на shutdown в обратном порядке. Внешние API/БД — ответственность сервиса, а не модуля: это перенос решения ADR-0002 (framework-owned state) на уровень зависимостей. Типизация `ctx.services` в handler-ах — через полный `ServiceMap` (fallback из спеки): декларация `services` остаётся гейтом сборки и валидации.
