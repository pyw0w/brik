# Component interactions (buttons) as first-class framework feature

Кнопки Discord — это отдельный тип взаимодействия (`MessageComponentInteraction`), который не является slash-командой: у него нет `options`, зато есть `customId`. Решение — сделать кнопки первоклассной частью контракта, сохранив модель «чистый Handler возвращает Result, ядро доставляет». Handler объявляет кнопки через новое поле `components` (`ComponentHandlerDef`) и рендерит их новым kind-ом `Result` — `'component'`. Ядро проставляет реальные `customId` по схеме `<handler>:<component>[:<payload>]` (имена Handler-ов глобально уникальны в Registry, поэтому префикс модуля не нужен) и роутит клики через `Registry.findComponent`. Клик — это тот же гейт-флоу, что и команда: предусловия и capabilities у компонента свои, `input` строится от имени Handler-а-владельца. Для перезаписи сообщения кнопки добавлен kind `'update'` (доставка через `interaction.update()`); из slash-команды он невозможен и деградирует до reply. Фреймворк по-прежнему не знает discord.js в рантайме контракта: `ButtonStyle` — строковые теги, маппинг на `ButtonStyle` discord.js живёт в адаптере.
