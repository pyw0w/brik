# Unified database subsystem: Document Collections + Direct SQL

Ядро предоставляет единую, встроенную подсистему базы данных на базе нативного рантайма `bun:sqlite`. Доступ к БД унифицирован и предоставляется как `ctx.db` во всех слоях фреймворка: в обработчиках (`HandlerRunContext`), жизненном цикле модуля (`ModuleSetupContext`, `ModuleReadyContext`), инициализации сервисов (`ServiceInitContext`) и хосте (`app.db`).

### Архитектурные принципы

1. **Двухуровневый API**:
   - **Документный уровень (`Collection<T>`)**: Простой CRUD (`insert`, `insertMany`, `find`, `findOne`, `update`, `delete`, `count`, `clear`) поверх JSON-документов в SQLite (`json_extract`, `json_patch`). Модулям не нужно объявлять DDL-схемы или запускать ручные миграции для стандартных структур данных.
   - **SQL-уровень**: Для сложных выборок, агрегаций и реляционных связей доступны `ctx.db.query<T>()`, `ctx.db.queryOne<T>()`, `ctx.db.run()` и `ctx.db.exec()`.
   - **Транзакции**: `ctx.db.transaction()` поддерживает асинхронные блоки и вложенные транзакции через SQLite `SAVEPOINT`.

2. **Изоляция модулей (ADR-0003)**:
   - Каждому модулю передается `ScopedDatabase`, автоматически изолирующий таблицы коллекций в пространство имён модуля: `_col_mod_<moduleName>_<collectionName>`.
   - Модули не могут случайно повредить коллекции других модулей; совместное использование данных происходит только через публичный API модуля.

3. **Замена `FileStore` на `SqliteStore`**:
   - Стандартный `ctx.store` (`get`, `set`, `delete`, `has`, `clear`) бесшовно переведён на общую таблицу `_kv_store` в SQLite с гарантией ACID, сохраняя 100% обратную совместимость с существующими модулями без блокирующей перезаписи JSON-файлов.

4. **Тестируемость**:
   - В тестах (`testing.ts`, `runHandler`, `runComponent`) по умолчанию инициализируется изолированная база данных в памяти (`:memory:`), гарантируя изоляцию и максимальную скорость тестов без мусора на файловой системе.
