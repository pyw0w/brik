# Framework owns state: channel memory + per-module KV store

В остальном «stateless per Input» ядро берёт на себя два вида состояния: диалоговую память по каналу (для многошаговых сценариев) и персистентный KV-store, неймспейсированный по имени модуля. Это осознанный компромисс: предоставить состояние в ядре — чтобы контрибьюторы могли «сохранить данные» одним `store.get/set()` без изучения БД; модули, которым нужна серьёзная персистентность, подключают свою внешнюю БД сами. Граница: ядро хранит простые данные модуля и память диалогов, но не владеет бизнес-схемами.
