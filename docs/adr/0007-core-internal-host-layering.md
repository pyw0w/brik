# Core/Internal/Host layering with a curated facade

Слои вынесены в явную структуру, потому что прежний god-object `bot.ts` смешивал контракт, реализацию и Discord. Теперь `src/core/index.ts` — курируемый фасад: единственная разрешённая для модулей точка входа (`arg`, `defineHandler`, `defineModule`, типы), без `export *` и без internals. Реализация — в `src/core/internal/` (Registry, Pipeline, store, logger, config), модулям недоступна; `src/core/testing.ts` — публичные тест-хелперы. Весь runtime-discord.js живёт в `src/core/discord/` (адаптер, gateway, registrar); host-сборка — в `src/app/` (compose/lifecycle/interactor) плюс `src/index.ts` как composition root с ручным DI (`composeApp`) и границами ошибок вместо связующего `Bot`. Контракт не тянет discord.js в рантайме: `ArgOptionType` — строковые теги (`'string'|'number'|'integer'|'boolean'`) вместо `ApplicationCommandOptionType`, маппинг в Discord-форму — только в registrar. Границы проверяет скрипт `scripts/check-boundaries.ts` (статический анализ импортов модулей), а не eslint, чтобы не тянуть eslint-стек ради одного правила. Тесты co-located рядом с кодом (нет отдельного `tests/`), работают in-memory через `runHandler`; покрытие — global-порог 70% (`bun test --coverage`). Команды регистрируются отдельным REST-скриптом `deploy:commands` без gateway. Всё это гоняется в CI на каждый PR (`.github/workflows/test.yml`).
