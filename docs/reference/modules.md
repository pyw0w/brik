# Справочник модулей и команд

Каталог модулей, включённых в бота по умолчанию (`bot.config.ts`), их команд и сервисов. Это не API-справочник (см. [Справочник API](../guides/module-api.md)), а карта того, **что сейчас умеет бот**.

## Модули и их команды

### `help`

Список всех команд бота. Строится по `CommandCatalog` (безопасное «что сейчас отвечает бот»).

- **`/help`** — показывает все команды, отсортированные по имени.

### `ping`

Проверка связи.

- **`/ping`** — отвечает «Понг!».

### `roll`

Броски кубиков. Запоминает последний бросок пользователя и умеет перебросить по кнопке.

- **`/roll`** — `dice` (формула `NdS`, по умолчанию `2d6`). Пример: `/roll 3d8`. Рендерит кнопку **«🎲 Ещё раз»** (component `reroll`), которая перебрасывает и обновляет сообщение.

### `forecast`

Погода в городе через сервис `weather` (демо).

- **`/forecast`** — `city` (город, по умолчанию `Москва`). Возвращает текст погоды.

### `anime`

Поиск аниме через Shikimori (сервис `shikimori`). Три команды:

- **`/search`** — `query` (название), `limit` (1–10). Список найденного с оценкой и годом.
- **`/top`** — `limit` (1–10). Топ аниме по рейтингу.
- **`/info`** — `target` (id или название). Карточка аниме: тип, статус, оценка, эпизоды, год, жанры, постер, описание.

### `buttons`

Демо кнопок: интерактивный счётчик.

- **`/counter`** — `start` (начальное значение). Рендерит кнопки **+1 / −1 / «Сброс»** (компоненты `step` с payload `1`/`-1` и `reset`). Значение хранится в store по пользователю и через `interaction.update()` перезаписывает сообщение.

### `logs`

Система логирования событий сервера (входы/выходы, сообщения, голос, наказания). Требует привилегированных интентов `GuildMembers`, `MessageContent`.

Категории логов: `mod`, `members`, `messages`, `voice`, `punishments`. Конфиг каналов хранится в store по `config:<guildId>`.

- **`/logs`** — управление каналами логов. Аргументы: `action` (`set`/`show`/`clear`, по умолчанию `show`), `type` (категория), `channel` (канал `#канал` или ID). Предусловия: `guildOnly` + право `ManageGuild`.

Логируемые события:

| Категория | События |
|---|---|
| `members` | участник вошёл / вышел, смена ника |
| `messages` | сообщение удалено, массовое удаление, сообщение изменено |
| `voice` | вошёл / вышел / перемещён в голосовом канале |
| `punishments` | тайм-аут (мут) |
| `mod` | действия модерации |

### `recorder`

Запись звука из голосового канала. Бот подключается к каналу, декодирует Opus в PCM и выдаёт говорящим файлы **WAV** (16 бит, моно, 16 кГц — стандарт для голосовых записей). Требует у бота прав `Connect` и `Speak` в голосовом канале.

- **`/record`** — `channel` (#канал или ID, опционально). Начинает запись: в указанном канале или в канале, где сидит автор команды. Лимит длительности — 30 минут по умолчанию (опция `recorder.options.maxDurationSeconds`; авто-остановка с доставкой файлов). Максимум файлов в сообщении — 10 (опция `maxFiles`).
- **`/record-stop`** — останавливает запись и прикладывает WAV-файлы говорящих (макс. 10 вложений; «никто не говорил» — сообщение без файлов). Длинные записи режутся на чанки по ~20 МБ (`<ник>-<время>-N.wav`) под лимит вложений Discord.
- **`/record-status`** — статус активной записи (канал, длительность, участников со звуком).

Авто-остановка и доставка файлов происходит и при выходе/перемещении бота из голосового канала и при разрыве соединения. Все команды — `guildOnly`; `/record-stop` требует `AttachFiles`.

### `voice`

Автосоздание и удаление временных голосовых каналов (Join to Create) в заданной категории. Пользователь заходит в настроенный канал создания («➕ Создать комнату»), бот создаёт для него персональный войс-канал в категории и переносит его туда. Когда последний участник покидает канал, бот автоматически удаляет его.

Для надёжности активные временные каналы сохраняются в SQLite-базе данных (`ctx.db.collection('temp_channels')`). При перезапуске бота (`onReady`) происходит восстановление: пустые или уже удалённые каналы очищаются из базы и Discord, а активные каналы берутся на сопровождение до выхода участников.

- **`/setup`** — быстрая настройка временных голосовых каналов. Предусловия: `guildOnly` + право `ManageChannels`.
  - `category` — категория для создаваемых комнат (#категория или ID).
  - `trigger` — триггер-канал для создания (#канал или ID).
  - `name` — шаблон названия (опционально, по умолчанию: `"🔊 {user}"`).
- **`/voice`** — управление временными голосовыми каналами. Предусловия: `guildOnly` + право `ManageChannels`.
  - `action`:
    - `setup` — настройка: требует `category` (ID или `#категория`) и `trigger` (ID или `#канал`), опциональный `name` (шаблон названия, по умолчанию `🔊 {user}`).
    - `show` — просмотр текущих настроек и числа активных временных каналов.
    - `clear` — удаление настроек и отключение автосоздания.
    - `cleanup` — ручная проверка и удаление пустых/осиротевших каналов.
  - `category` — категория для создаваемых комнат (#канал или ID).
  - `trigger` — триггер-канал для входа (#канал или ID).
  - `name` — шаблон названия (например, `"🔊 {user}"` или `"Комната {user}"`).

## Сервисы

Сервисы — это внешние зависимости модулей (ADR-0008), живут в `src/services/`. Строятся только те, что задекларированы включёнными модулями.

### `weather` (демо)

Эмуляция внешнего API погоды. Модуль `forecast` использует `services.weather.now(city)`.

Опции: `apiKey?` (не обязателен — значение чисто демонстрационное).

### `shikimori`

Реальный GraphQL-клиент [Shikimori](https://shikimori.one). Использует модуль `anime`.

Опции:
- `userAgent` — **обязателен** (Shikimori требует User-Agent приложения). По умолчанию подхватывается из `SHIKIMORI_USER_AGENT` (`bot.config.ts`).
- `minRequestInterval` — минимальный интервал между запросами (троттлинг, чтобы не ловить лимиты API).

Методы `ShikimoriApi`: `search(query, limit)`, `top(limit)`, `animeById(id)`.

## Как добавить в этот каталог

После добавления модуля в `src/modules/` обновите список выше (команды, аргументы, компоненты, сервисы). Свежее состояние включённых модулей всегда смотрите в `bot.config.ts`.
